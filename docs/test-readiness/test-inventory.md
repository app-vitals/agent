## Per-category detail

### 1. Pure business logic
`lib/` helpers, admin manifest/template merge logic, runtime markers/format/context-stamp, chat errors. Redaction and crypto helpers are `critical` (security boundary).

### 2. Service-boundary code
Prisma-backed admin and chat services, the Kubernetes client/provisioner, runtime cron/setup/boot (git, filesystem, child processes). Integration tests need real Postgres (see the squadron-style local Postgres note) and a fake Kubernetes API.

### 3. HTTP routes / public API
`admin/src/*-api.ts`, `chat/src/routes/*`, `runtime/health.ts`. Smoke covers the wire contract only; business rules stay at unit/integration.

### 4. Error / failure paths
Agent deletion and repo-removal (data loss), stall reaper, cron failure reporting, process-tree-kill. Unit plus integration only; never canary.

### 5. External integrations
GitHub (App + Enterprise), Slack, Anthropic identity, Google/Okta, web push, TTS/STT. Integration with recorded fixtures.

### 6. User journeys
Admin UI sign-in, agent create/edit, template and settings flows (Playwright, `admin/e2e/`), plus a runtime Slack-message → Claude run → reply journey (not currently an automated E2E).

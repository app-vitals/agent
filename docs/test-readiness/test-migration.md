# Test Migration

> Phase 3 of the test-readiness pipeline. Reconciles the Phase 2 blueprint (`test-system.md`) and the Phase 1 inventory (`test-inventory.md`) against the tests that exist on `main` today.
>
> Generated by `/test-migration` on `2026-11-18`.

## Method and limits

- **Discovery:** `git ls-files` for `*.test.ts`, `*.spec.ts`, `*.e2e.ts`. **350 test files**: 195 `.unit.`-suffixed or plain, 95 `.integration.`, 40 `.smoke.`, 9 Playwright `.e2e.ts`, 0 `.canary.`, plus 11 not matching a layer suffix (fixture/support tests).
- **Not measured:** per-test runtime and line/branch coverage. CI runs plain `bun test` with no coverage flag, so no `lcov` data exists; the speed criterion is therefore **unverified** and no test is bucketed on speed.
- **Bucketing is by file group**, using layer suffix, owning module and a name-based sibling check (source file `x.ts` has a `x.*test.ts` next to it, or its module is imported by some test). Individual test bodies were not read. Treat per-file calls as approximate; the group totals are the reliable part.
- **Unverified claims from Phase 2:** the blueprint's "to create" helpers were not checked for existence one by one. `chat/src/test-fakes.ts`, `admin/src/*.fixtures.ts` and `runtime/fixtures/stream-json/` do exist.

## Risk callouts

- No test is marked rebuild, so there is no passing-but-false-confidence call to make. That is a limit of this phase's method, not evidence the suite is sound.
- **Coverage is unmeasured.** The 80% floor cannot be enforced until the coverage step exists; the real gap list will appear on the first lcov report.
- **Mixed-layer single job** hides which layer is slow; the 15-minute job timeout is the only budget guard today.
- Large files (`admin-ui.ts`, `admin-ui-pages.ts`, `agents-api.ts`, `slack.ts`, `setup.ts`, `claude.ts`, `agent-provisioner.ts`) have many tests nearby but their depth is unverified.
